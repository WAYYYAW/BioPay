# BioPay 1.0.3 业务逻辑及性能审查

## 支付流程

1. 微信原始 `setInputEditText` 完成后，读取开关、密文和密码存储版本，初始化支付会话。
2. 支付会话和每次认证分别持有递增 ID。取消、关闭或切换会话后，旧认证回调不能完成新的认证或恢复新会话界面。
3. 验证成功后才解密；输入计划只保存按键弱引用，密码字符立即清零。输入前检查六位 ASCII 数字和所有按键是否存在。
4. 一个 Runnable 按顺序发送触摸事件，并管理最后的界面恢复延迟。会话、键盘或附件状态改变时取消整个计划；触摸事件始终回收。
5. 取消、异常、分离、超时、Activity 销毁及热重载会恢复已隐藏的视图并移除延迟任务。音量键首次按下切换认证和手动输入，重复按下不重复触发。

## 已修复问题

| 问题 | 修改 |
| --- | --- |
| 认证状态依赖 Context 的字段标志，旧回调可能影响后续认证 | 独立认证 ID，终态使用原子比较并清除，只接受一次 |
| 解密准备失败时删除已保存密码 | 保留密文，恢复手动输入，允许重试 |
| 设置页与支付共用取消信号 | 设置对话框拥有自己的认证 ID 和取消信号；关闭后取消 |
| 加密失败仍提示启用并关闭设置 | 保存回调返回成功状态，仅成功时提示并关闭 |
| 开关、密码、模式分多次写入偏好 | 启用和模式一起写入；新密码、版本、开关和模式一次写入 |
| 只检查密码长度 | 保存、加密、解密和输入均检查六位 ASCII 数字 |
| 捕获原方法异常后再次执行原方法 | 微信原方法执行位于模块异常恢复之外，异常正常传播 |
| 透明恢复只遍历当前键盘或直接丢弃历史状态 | 按保存的视图恢复；重置同时恢复键盘与窗口 |
| 输入后的恢复任务无法取消，字符数组未清零 | 任务统一使用 Handler token；生成计划后清零字符数组 |
| 清理定时器销毁后不重启，闲置时仍启动 | 支付开始时启动，结束时停止，下次支付重新启动 |
| system_server 创建支付状态与 Handler | 延迟初始化 AppWiring |
| 热重载遗留旧生命周期回调 | 卸载前注销回调并清理会话，新代重新注册 |
| 日志关闭在主线程等待和写文件，导出可能丢失已刷新内容 | 后台保存不可变快照，主线程接收完成通知；刷新不清空最近日志 |
| 未开启日志仍格式化时间 | 提前检查 DEBUG 与运行状态 |

## 性能变化与边界

- 自动输入从六个数字 Runnable 加一个恢复任务，改为一个顺序执行的 Runnable；每一步只保留下一次调度。
- 资源 ID 使用十项数字缓存；输入期间不再重复查询 ID 和遍历键盘查找按键。
- 删除当前支付路径已不使用的 TopActivityProvider 反射初始化。
- 普通 Activity Context 查询使用快速返回，只有包装 Context 才遍历。
- 以上是代码路径和任务数量的变化，未测量设备耗时或内存，因此不提供性能提升百分比。

## 保留的兼容行为

Class 1 的 system_server 三个 hook 及现代 Xposed `system` 作用域保持不变。它们仍改变系统对生物识别强度的判断。指纹模式请求 STRONG，面容和双选请求 WEAK；面容关闭额外确认。Android BiometricPrompt 按可用传感器选择，不保证只调用某一模态。密钥继续使用 `_compat_v3`，不增加密钥迁移或重新录入要求。

## 检查范围

完成源代码审查及 diff 格式检查。构建任务为 `assembleDebug assembleRelease --offline`，包含 release 的 R8 混淆与资源缩减；不包含单元测试或设备支付验证。仍需设备确认支付成功、取消后手动输入、再次认证、设置保存/清除、外部支付页面重建和日志导出。

Release 签名配置仍缺失，产物为 unsigned APK；debug APK 使用 debug 签名。
